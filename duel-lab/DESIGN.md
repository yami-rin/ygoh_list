# Astra Duel Lab — 要件・設計

## 要件と構成
人間と実際のGPT-6 Astraが、通常M∀LICEを使いOCGの自動処理で対戦する。
メイン40〜60枚、EX15枚以下、2026年7月OCG禁止制限を適用する。
MDPro3のUnityクライアントを使用し、立体フィールドと枠・属性・レベル・効果欄を含むカード全体を表示する。

```text
人間 → MDPro3 UI → 内蔵YGOProサーバー・カードスクリプト
                         ↕ 対戦プロトコル
                  WindBotクライアント
                         ↕ AstraDecisionBridge
                  localhost:8788 / native-bridge.mjs
                         ↕ 構造化選択
                  Codex CLI / gpt-6-astra
```

召喚条件、素材、コスト、チェーン、効果、戦闘、LP、勝敗は既存エンジンが処理する。
WindBotは通信と自身の視点の状態管理に使用し、戦略の選択をAstraに置き換える。
選択肢が強制される場合は自動で返す。モデル名だけ変更した固定AIではない。

## Astraと情報境界
既存Codexログインと固定版CLIを使い、選択ごとにgpt-6-astraを呼び出す。
空の一時ディレクトリ、ユーザー設定無効、シェル・検索ツール無効で実行する。
自身の手札・EX・デッキ構成と公開盤面を渡す。相手手札・伏せカードID・山札順は渡さない。
同じ試合の短い戦略メモは次の判断へ引き継ぐ。新規試合では初期化する。
候補番号、枚数、重複、カウンター合計を検査してから応答する。
接続はループバック限定、起動ごとのトークンを使い、ブラウザOriginからの呼び出しは拒否する。
接続失敗はログとクライアントの通知に出し、ゲーム設定のリトライで再戦する。途中復元は未対応。

## 素材と再現性
MDPro3ソース、対応Unity、画面素材、プリセット41種類のカードアートを固定版・ハッシュで取得する。
画像はシミュレーター向け既存素材を優先する。MD本体からの読み取り専用抽出は任意の補完。
コード・スクリプト・取得ロックをGit管理し、第三者ソース、バイナリ、カード資産、認証設定は含めない。
setup-native.pyが上流への変更を適用し、build-native.ps1でクライアントを構築する。
start-native.cmd、start.ps1、npm startが同じネイティブ版を起動する。
終了時はランチャー所有の接続プロセスも停止する。

## 検証済み範囲（2026-09-07）
ネイティブ画面で日本語メニュー、カード全体、立体フィールド、実Astraの選択を確認した。
White Rabbitの召喚・罠セット、UNDERGROUNDからDormouseの除外・300LP支払い・帰還を確認した。
実サーバーの接続試験で正常デッキの受理、禁止・制限超過・準制限超過・同名4枚の拒否を確認した。
ブラウザ試作用の実core試験は召喚、M∀LICE効果、チェーン無効、リンク、戦闘勝敗、情報遮断を検証する。
これらはネイティブ版の全カード・全裁定・一試合完走を保証するものではない。
Astra判断は実測で概ね9〜16秒/選択。強さや勝率は未測定で、通信状況により長くなる。

## 範囲外
オンライン公開サーバー、MD公式への接続、課金・アカウント連携、すべての追加衣装・背景素材の取得。
ブラウザ版はエンジン検証用としてstart:browserに残す。製品の対戦画面はMDPro3を使用する。
